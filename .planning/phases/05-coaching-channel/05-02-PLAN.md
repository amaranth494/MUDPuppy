<objective>
Close the two ways the safety checker is wrong today. On staging it blocked `c chill touch golem` and `c static blast crystal` — the tutorial's own fights — reading "another player or entity" into a rule that only says another player; those wrong blocks count toward switching autopilot off, so the AI cannot finish the tutorial. And in the other direction, `ReviewAnswer.Blocked` is a plain Go `bool`: an answer that omits the field decodes cleanly as `false`, which the driver reads as "not blocked" and sends the command.

Purpose: D-23 and D-24 are two of the three high items the owner said must be fixed in this phase. Both have exact code locations and both are small. The over-blocking fix also has to be measurable, which means the two real false blocks become corpus items and get sampled more than once, because one sample cannot tell a wrong answer from an unreliable one (Phase 4 D-29).
Output: a verdict that can be absent and is fail-closed when it is, a reviewer instruction that says fighting is ordinary play and that the memory notes came from the other model, and the corpus items that make both claims falsifiable on a live run.

This plan changes no prompt the player model sees, adds no endpoint, and does not run the live corpus — plan 05-11 does that.
</objective>
