<objective>
Put a real backstop behind AI-player's pacing. The register says the last-resort speed limit on commands does not count the AI's commands, and the code says why: `icm.Dispatcher.Dispatch` returns for a command with no registered handler — which is every plain MUD command the AI sends — before `RecordExecution` is ever reached. So the AI's sends are checked against a counter they never contribute to. Worse, that counter is never reset, so routing AI sends through it as it stands would eventually refuse every AI command in a long-running process.

Purpose: D-25 is the third high item the owner said must be fixed in this phase, and he added the condition that the limiter be a setting he can configure. The right fix is a small, dedicated, per-user check the driver makes immediately before it dispatches, independent of the dispatcher's differently-scoped circuit breaker — and an AI setting on the profile, blank meaning the server's default, exactly like the other AI settings.
Output: a per-user token bucket in the driver, a refusal that behaves like every other transient failure, a fourth AI setting from database to browser, and a flood test that proves the limit holds.

`internal/icm/dispatcher.go` is not edited by this plan. Its existing behaviour for hand-typed commands must stay exactly as it is.
</objective>
