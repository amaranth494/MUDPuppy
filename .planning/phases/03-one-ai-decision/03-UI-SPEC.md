# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope actually covered here** (per orchestrator instruction — nothing else is in Phase 3 UI):
(a) the floating, minimizable **AI Assist panel** on the play screen (D-06 to D-08): default position/size, collapsed tab, open/close affordance, coexistence with the full-width terminal, message layout for one decision, system lines for state changes, empty state, reload-after-refresh state — no message input (Phase 5);
(b) the terminal line `[AI-ASSIST > north]` replacing local echo for AI-issued commands (D-09), styled so it never looks like a bracketed notice or a typed echo;
(c) the `#AUTO` grammar line for anything other than ON/OFF (D-11), retiring the Phase 2 `#AUTO STATUS` line;
(d) the D-13 failure notice (panel + terminal, one wording per failure kind) and the D-20 not-configured refusal notice;
(e) the **Logs** section in Settings (D-16): nav entry, "Open Logging" button opening a new tab, and its copy;
(f) the **per-profile log page** (D-17): two-pane layout, session list, transcript, human/AI/game line marking, empty states, sign-in-required state, page title;
(g) the regression invariant: hand play on a profile with no AI activation looks exactly as it does today (carries Phase 2 D-12 forward).

All tokens below are carried over unchanged from `01-UI-SPEC.md` and `02-UI-SPEC.md`. This phase adds exactly two new CSS custom properties (an AI-identity accent and a human-command identity color, both justified below), new CSS class blocks for the panel/tab/logs page, and the copy strings this phase requires. No component library, no shadcn.

Usage in this phase:
- **Display (20/700)** — the AI Assist panel header title ("AI Assist"), matching `.modal-title`'s existing 20/700 treatment; the Logs page's own top-level heading ("Session Logs — {profile name}").
- **Heading (24/700)** — the Logs section's `<h3>Logs</h3>` inside Settings, matching every other `.settings-section h3`.
- **Body (16/400)** — a decision's reasoning text, its highlighted command line, transcript game-output lines, empty-state body copy.
- **Label (14/400)** — panel system lines (engaged/waiting/resuming/disengaged/refused/failed), Logs session-list row date/time text, transcript human/AI command-line prefixes.

Only two weights exist anywhere in this contract: 400 (body, labels, transcript text) and 700 (headings, the panel title, the minimized-tab label, the decision's command highlight). Never introduce 500/600.

## Color

Existing tokens in `index.css`, reused as-is — unchanged from Phases 1-2:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a0a` (`--color-bg`) | Page background; the AI Assist panel's decision-card background; the Logs page background (unaffected by this phase) |
| Secondary (30%) | `#111111` (`--color-bg-secondary`) | AI Assist panel body background; minimized tab background; Logs page's transcript pane background |
| Accent (10%) | `#00ff00` (`--color-success` / `--color-text`) | Reserved for: engaged/resuming panel system lines (matches Phase 2's autopilot-ON accent exactly), and nothing new — the "Open Logging" button reuses `.btn-primary`'s existing green, the same primary-CTA reservation established in Phase 1 |
| Secondary state | `#ffff00` (`--color-warning`) | Reserved for: the waiting panel system line (matches badge WAITING) |
| Neutral | `#888888` (existing hardcoded precedent from `.session-badge.status-disconnected` / `.autopilot-badge.state-off`) | Reserved for: the disengaged panel system line — this is the panel's HTML counterpart to the terminal's ANSI `white`, since no `--color-white`/neutral token exists; `#888` is the established neutral precedent in this codebase |
| Destructive | `#ff4444` (`--color-error`) | Reserved for: every refusal and failure notice (engage-gate, D-20 missing-config, all six D-13 failure kinds, the D-11 unknown-option line), in both the panel and the terminal |

### Two new tokens this phase introduces (add to `:root` in `index.css`)

| New token | Value | Reserved for |
|-----------|-------|---------------|
| `--color-ai-accent` | `#ff66ff` (visually matches xterm's rendered `brightmagenta`, ANSI `\x1b[95m`, already used nowhere else in the app) | The terminal's `[AI-ASSIST > command]` line; the AI Assist panel's command highlight inside a decision card; the minimized tab's icon-adjacent accent when a decision is in flight; the Logs transcript's AI-issued line. Never used for buttons, body text, or any element unrelated to "the AI issued this." |
| `--color-human-command` | `#00ffff` (visually matches xterm's rendered `brightcyan`, ANSI `\x1b[96m`, already the terminal's existing human-typed-echo colour — this token formalizes it for the first HTML surface that needs it) | The Logs transcript's human-issued line only. The terminal itself is unaffected (it already renders human echo in this colour via ANSI, unchanged). |

**Why two new tokens are justified, not scope creep:** Phase 2 already established the precedent that a locked semantic distinction gets its own reserved colour beyond the base four roles (the WAITING badge state, `--color-warning`, is exactly this). Phase 3 introduces a new locked semantic distinction that Phases 1-2 never needed — "who issued this command: the owner or the AI" — and D-09 explicitly requires typed and AI-issued commands to "never look alike." Reusing the existing accent green (already reserved for "autopilot is ON") or red (already reserved for "refused/failed") for this purpose would conflate unrelated signals. Both new tokens are reserved for exactly the named elements above and nowhere else.

### 2. Terminal AI-issued command echo (`PlayScreen.tsx`, extended)

On receipt of the new `MsgTypeAI` "command" event, the terminal writes `[AI-ASSIST > {command}]` in place of the normal typed/automation echo, using the same bracketed-notice mechanism (`echoLocal(message, { color: 'brightmagenta' })` or an equivalent direct terminal write using ANSI `\x1b[95m`) that already produces `[Disconnected]`/`[ERROR]`/the wheel-grab notice. The game's own echo and response for that command follow via the existing unchanged MUD→client relay. No cyan human-typed echo line is written for an AI-issued command — the magenta bracket line fully replaces it (D-09).

### 3. `#AUTO` grammar line (`evaluator.ts`'s `case 'AUTO':`, extended)

The existing `rawArg === '' || rawArg === 'STATUS'` branch (currently mapped to `action = 'status'`) is retired. Any argument other than `ON`/`OFF` — including a bare `#AUTO` and `#AUTO STATUS` — now prints the single line `[Autopilot: don't know what you're talking about. Your options are ON or OFF]` in red (`getAnsiColorCode('red')`), reusing the exact colour the current invalid-argument default case already uses at line 1188. This is a terminal-only line (a directive's own reply), never surfaced in the AI Assist panel.

```css
.logs-transcript-line.ai { color: var(--color-ai-accent); }
.logs-transcript-line.game { color: var(--color-text-dim); }
.logs-transcript-empty {
  color: var(--color-text-dim);
  font-style: italic;
  text-align: center;
  padding: var(--spacing-lg);
}
```

**Left pane:** one row per session, `Session {date} {time}` label formatted `YYYY-MM-DD HH:MM:SS` (24-hour, ISO-consistent with Phase 1's date-format precedent, extended with time since multiple sessions can share a date). Clicking a row loads its transcript into the right pane and marks it `.active`. Empty state (`.logs-session-empty`): `No sessions recorded yet for this profile.`

**Right pane:** the selected session's transcript, one `.logs-transcript-line` per stored line: human-issued lines render as `> {command}` in `--color-human-command`; AI-issued lines render as `[AI-ASSIST > {command}]` in `--color-ai-accent` (the identical string the terminal and panel already used live — one canonical label for the same fact everywhere it appears); game-output lines render with no prefix in `var(--color-text-dim)`. Before any session is selected: `.logs-transcript-empty` reads `Select a session on the left to view its transcript.`

**Page title:** both the `<h2>` in `.logs-page-header` and the document `<title>` read `Session Logs — {profile name}`.

## Regression Invariant (carries Phase 2 D-12 forward, non-negotiable)

AI activated or not"), so the Logs section appears for every profile exactly the same way regardless of AI activation. Only the AI Assist panel and the `[AI-ASSIST > ...]` terminal line are gated on AI activation.
- Ordinary connect, disconnect, typing, and command echo behave exactly as Phase 2 left them, including the existing badge, bracketed notices, and `#AUTO ON`/`#AUTO OFF` behaviour.

For any profile that **has** accepted the policy, with autopilot never engaged this session: the AI Assist panel is present and open per D-07, showing only its empty state — no decision cards, no system lines, no new terminal colour appears until `#AUTO ON` is actually typed.

## Claude's Discretion (visual contract only — does not change owner-visible behavior)

- **Panel default position/size** (380×480px, bottom-right, 96px bottom offset): D-06 only locks "floating, minimizable... terminal keeps full width"; the exact geometry is chosen to sit clear of `.input-row` without covering the terminal, using only multiples of 4.
- **Two new CSS tokens** (`--color-ai-accent` #ff66ff, `--color-human-command` #00ffff): justified above under Color — needed because D-09 requires human vs. AI commands to "never look alike," a distinction Phases 1-2 never had to encode in CSS (the terminal already told them apart via ANSI; this phase's panel and Logs page are the first HTML surfaces that need the same distinction in CSS). Exact hex values may be nudged by the executor to visually match xterm's actually-rendered `brightmagenta`/`brightcyan` if the theme renders them differently than these approximations.
- **Reasoning-then-command layout inside a decision card** (`→ {command}` on its own bold line under the reasoning paragraph): D-10 locks the content ("short why, then exactly one command"); the arrow-prefixed second line is the chosen visual separation between the two parts.
- **Minimized tab shows a live autopilot-state dot**: informational only, derived from the same `autopilotState` context value the header badge already reads — not a new source of truth, and not required by any D-06 to D-11 decision, but a low-cost consistency touch (same discretion class as Phase 2's badge tooltip).
- **Panel reload behavior re-renders only persisted decision rows, not transition system lines**: explicit resolution of an ambiguity in D-08/D-12 (see Layout section above) — decided in favour of matching Phase 2's own precedent (only current state survives a refresh, not a history of transitions).
- **Exact wording of the six D-13 failure notices**: D-13 locks the six failure *kinds*, not their sentences; each notice names the failure plainly and repeats "Autopilot disengaged" for consistency with D-13's own "lands autopilot on OFF" behaviour, mirroring Phase 2's own bracket-notice voice.
- **D-11's unknown-option line reuses the existing red "invalid argument" precedent** already in `evaluator.ts` (line 1188) rather than inventing a new colour meaning for "the owner mistyped a directive."
- **Logs nav icon (📜)** chosen for thematic fit and to avoid clashing with any of the six existing Settings glyphs.
- **Log page reuses the global `Header` and `AuthGuard`** rather than a bespoke minimal page — keeps the new tab visually and behaviourally consistent with the rest of the app at zero extra design cost, and gives "sign-in protected" for free (D-17).
- **Session list date/time format** (`YYYY-MM-DD HH:MM:SS`, 24-hour): no existing full timestamp pattern in the codebase to match exactly; extends Phase 1's ISO-date precedent with time-of-day since a profile can have many sessions per day.
- **Transcript line prefixes** (`> {command}` for human, `[AI-ASSIST > {command}]` for AI, no prefix for game text) rather than colour-only differentiation: colour alone is a weaker scanability signal in a plain-text transcript pane than in the panel's card-based layout, so a short textual prefix is added: for the AI-issued case, this is not a new string — it is the exact same bracketed label already defined for the live terminal and panel, applied to a third surface.

None of these affect what the owner sees in terms of information or interaction — only implementation-level styling, geometry, and copy-formatting choices, consistent with "no speed bumps" guidance. Every locked wording from D-11, D-13's failure list, D-20, and Phase 1/2's carried-forward strings is reproduced verbatim above; nothing here alters owner-visible state semantics.
