<objective>
Give the owner the logbook. Settings gains a Logs section per connection profile with one button that opens a log page in a new browser tab — the current tab never navigates. That page lists the profile's sessions by date and time on the left and shows the selected session's transcript on the right, with the owner's own commands, the AI's commands and the game's output told apart at a glance.

Purpose: D-16 and D-17 are the owner's own design, down to the tab behaviour: "the modal on the right lights up with open up logging, and then it'll jump you over to the page. But importantly, I don't want it to move away. The current tab stays where it is. It has to open it in a new tab." The transcript itself already exists — plan 03-05 records it and serves it — so this plan is the surface that makes it readable.
Output: two fetch functions, one new SPA route and page with its CSS, and one new Settings section.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → the transcript read endpoints | A caller supplies a connection id from the URL and asks for stored game text |
| Stored game text → rendered DOM | Transcript content is untrusted remote text, including other players' words |
| Settings tab → the opened tab | A new tab opened by an anchor can reach back through `window.opener` unless told not to |

## STRIDE Threat Register

| Threat ID | Category | Severity | Component | Disposition | Mitigating Task |
|-----------|----------|----------|-----------|-------------|-----------------|
| T-3-04 | Information Disclosure (IDOR) | High | the log page reading another owner's transcript by editing the URL | mitigate | Server-side: plan 03-05's endpoints resolve ownership through `GetProfileByConnection`; client-side: 03-11-02 takes the connection id only from the route and never merges profiles, so a hand-edited URL is refused by the server rather than trusted by the page |
| T-3-37 | Tampering (script injection) | Medium | transcript text rendered on the log page | mitigate | 03-11-02 — rendered as JSX children with a source assertion that `dangerouslySetInnerHTML` appears nowhere on the page |
| T-3-40 | Tampering (reverse tabnabbing) | Low | the new tab reaching back through `window.opener` | mitigate | 03-11-03 — `rel="noopener noreferrer"` on the anchor, asserted in the acceptance criteria |
| T-3-41 | Denial of Service (session disruption) | Medium | a second tab mounting the play screen and disturbing the live game session | mitigate | 03-11-01 — the `/logs/:connectionId` route renders outside `AppContent`, asserted by the single-occurrence `PlayScreen` grep |
| T-3-09 | Information Disclosure (policy) | Medium | full transcripts, including other players' speech, now readable in a browser page | defer to security review | On the Phase 3 agenda by plan 03-13 against the policy's data-handling section; this page adds no export, no search and no cross-profile listing, which is the narrowest surface that satisfies D-17 |
| T-3-SC | Tampering (supply chain) | Low | `frontend/package.json` | accept | This plan installs no package; it must be unchanged at plan end |
