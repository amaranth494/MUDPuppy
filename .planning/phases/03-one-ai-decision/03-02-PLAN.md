<objective>
Teach the server to ask a model a question, and take every fact about which model and which key entirely from the environment. This plan builds `internal/gemini` — a hand-written `net/http` client for one endpoint, `generateContent`, constrained by a response schema so the answer arrives as `{reasoning, command}` — and extends `internal/config` with a model registry read from environment variables, a default entry, and the `AIConfigured` predicate plan 03-06 refuses engagement on.

Purpose: ROADMAP criterion 3 says model names and API key come from environment configuration and nothing is hard-coded. D-18 fixes the shape: a default plus any number of named entries, each with its own endpoint and key, so a second vendor plugs in later without touching profiles. D-20 fixes the failure mode: absence is not a startup fatal. The Gemini model lineup is documented as moving within this project's own timeline (RESEARCH, State of the Art), which is exactly why no model identifier may appear in Go source.
Output: a new `internal/gemini` package with `httptest`-backed tests, and `internal/config` extended plus its first test file.
</objective>

    Declare `type Answer struct { Reasoning string \`json:"reasoning"\`; Command string \`json:"command"\` }` — the shape the model is constrained to produce (D-10: a short plain-language why for the owner, plus exactly one command).

    Declare `type Kind string` with the constants `KindTransport`, `KindBadRequest`, `KindAuth`, `KindRateLimited` and `KindMalformed`; `type Error struct { Kind Kind; Status int; Message string }` implementing `error`; and `func ErrorKind(err error) Kind` returning the kind of a `*Error` and `KindTransport` for anything else. These five kinds are what plan 03-08 maps onto D-13's failure notices, so do not collapse them.

    Declare `type Client struct` holding an `*http.Client`, and `func NewClient(timeout time.Duration) *Client` defaulting to 30 seconds when the timeout is zero.

    Declare `func (c *Client) GenerateContent(ctx context.Context, endpoint, model, apiKey, systemInstruction, userText string) (*Answer, error)`:
    - Build the request body with `json.Marshal` exactly as RESEARCH's Gemini API Reference specifies: `systemInstruction.parts[0].text` carries `systemInstruction`; `contents[0]` has `role: "user"` and `parts[0].text` carrying `userText`; `generationConfig` sets `responseMimeType: "application/json"` and a `responseSchema` of type object with string properties `reasoning` and `command`, both required. The schema is what makes a malformed answer a clean JSON-decode failure instead of a text-parsing guess.
    - POST to `strings.TrimRight(endpoint, "/") + "/v1beta/models/" + model + ":generateContent"` via `http.NewRequestWithContext`. Set `x-goog-api-key` to `apiKey` and `Content-Type` to `application/json`. Never put the key in the URL and never build a `?key=` query string — a URL with the key in it lands in every access log, proxy log and Go transport error string, which is precisely the class of problem DR-2-01 exists to close (RESEARCH Pitfall 3). Put that reason in a comment on the header line so it survives a future refactor.
    - Map the response: a transport or context error → `KindTransport`; 400 → `KindBadRequest`; 401 or 403 → `KindAuth`; 429 → `KindRateLimited`; any other non-200 → `KindTransport` with the status recorded. For non-200 responses read at most a bounded amount of the body (for example 4KB) and put the vendor's `error.message` into `Error.Message` when it parses, never the request body and never any header.
    - On 200, decode the envelope `{candidates:[{content:{parts:[{text:string}]}}]}`, then decode that `text` field a second time into `Answer`. This double decode is the contract, not an edge case (RESEARCH Pitfall 5): skipping it shows the owner raw JSON where the reasoning should be. Empty `candidates`, an empty `parts` list, or a second decode that fails → `KindMalformed`.
    - Return the `*Answer` unmodified. Do not trim, rewrite or validate the command here — command validation is a security boundary that belongs in the driver, in front of the dispatcher (plan 03-08, T-3-01). Say that in the doc comment so nobody adds it in two places.
    - Add no `log.Printf` anywhere in this file. Nothing about the outbound request — URL, headers, key, prompt, answer — is logged here; plan 03-08 logs the outcome with ids and lengths only.

    Create `internal/gemini/client_test.go` in `package gemini`, driven by `httptest.NewServer` (the first use of `httptest` in this repo; use it directly per stdlib convention) with the server's own URL passed in as `endpoint`.

    - `TestGenerateContentErrors` as a table over status codes and bodies: 400, 401, 403, 429, 500, an empty `candidates` array, and a `text` field that is not valid JSON — asserting the returned `ErrorKind` for each and that `*Answer` is nil and nothing panics.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Go process → Google's API over the public internet | An API key crosses this boundary on every call and must never be recorded on either side |
| Environment → process config | The key and model identity arrive as environment variables set on Railway staging by the owner |
| Vendor response → process | The model's answer is untrusted text that will be turned into a game command by a later plan |
