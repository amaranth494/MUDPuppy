<objective>
Carry the decision to the owner's screen, and make it still be there after a refresh. The server pushes each decision and each failure notice to the open play screen over the websocket the moment it happens, and exposes the connection's stored decisions as a list so a reloaded page can rebuild what it missed.

Purpose: REQ-reasoning-visibility has two halves — "appear in the play screen as they happen" and "stored in the session log", where they survive a page refresh. Plan 03-08 stored them; this plan delivers them. The two mechanisms are deliberately different: a live push for what happens now, and a REST read on mount for what happened before, which is the same pattern Phase 2 used for the autopilot badge because no per-user connection registry existed to make an attach-time websocket message reliable. This plan adds that registry for the push half.
Output: a new websocket message type with a typed payload, a per-user client registry, the driver's notifier wiring, and one owner-scoped read endpoint.
</objective>
