<objective>
Make the server say plainly that it cannot drive. When the default model or its key is absent from the environment, the server still starts, still connects games, still lets the owner hand-play — and `#AUTO ON` is refused with one clear sentence while the switch stays off.

Purpose: ROADMAP criterion 3 ends with "the server fails clearly if they are absent when engagement is attempted", and D-20 fixes both halves of that: not a startup fatal, and a specific refusal at the moment of engagement. This is also the one Phase 3 behaviour that is verifiable on staging *before* the owner sets the Gemini variables, which is why it is built early and proved first.
Output: a second gate in the `Autopilot` handler's `"on"` branch and the tests that pin it.
</objective>

    In `internal/session/handler.go`, add a second engage gate to the `Autopilot` handler's `"on"` branch only. Leave the `"off"` branch, the `"status"` action, the gate resolution block and every existing outcome exactly as Phase 2 left them.

    Order matters and must be exactly this: the existing Phase 1 policy-gate check runs first and, when it refuses, returns `refused-gate` with `store.EngageGateRefusalMessage` unchanged; only when the policy gate allows does the new check run. Two refusals with two distinct sentences, never one string trying to encode both reasons.

    The new check is `if h.config == nil || !h.config.AIConfigured()`. On refusal: read the current state with `h.manager.AutopilotStateFor(userIDStr)`, set `resp.State` to it, set `resp.Outcome` to the new value `refused-not-configured`, set the response's message field to `Autopilot refused: AI is not configured on this server` (the same field the gate refusal already uses, so the browser needs no change), emit one log line in the established format `[AI-PLAYER] autopilot user_id=%s connection_id=%s old=%s new=%s cause=refused-not-configured` with old and new both the current state, send the JSON and return. `EngageAutopilot` is never called, so the switch cannot move and no driver can ever be invoked on this path.

    A nil `h.config` refuses — a missing dependency fails closed, never open, the same discipline the `EngageGate` doc comment states at `handler.go:27-30`. Put that sentence in a comment on the check.

    Add `refused-not-configured` to the `Outcome` enum comment on `AutopilotResponse` (`handler.go:107-113`), following the existing `refused-` + reason naming.

    Never log the model name, the endpoint, the key, or any part of the registry on this path — the refusal line carries ids, states and the cause only (T-3-02).

    Add to `internal/session/handler_test.go`, following the file's existing construction and request-faking style:
    - `func TestAutopilotHandler_AIConfigRefusal(t *testing.T)` with subtests:
      - `refuses_on_when_unconfigured`: a handler built with a `*config.Config` whose registry is empty and an `EngageGate` callback that allows; POST `{"action":"on"}`; assert HTTP 200, `outcome` is `refused-not-configured`, the message is the locked sentence character for character, and `state` is `off`.
      - `nil_config_refuses`: the same with a nil `*config.Config`; assert the same outcome rather than a panic.
      - `gate_refusal_takes_precedence`: an unconfigured AI *and* a refusing `EngageGate`; assert the outcome is `refused-gate` and the message is the Phase 1 refusal string, proving the two refusals did not blur.
      - `engages_when_configured`: a complete registry and an allowing gate, with a connected session seeded on the manager; assert the outcome is `engaged` (or `refused-no-session` when no session is seeded — assert whichever the seeded state makes correct, and seed a connected session so the positive path is the one covered).
      - `off_is_unaffected_when_unconfigured`: with an unconfigured AI, POST `{"action":"off"}` and assert the outcome is `disengaged` or `already-off` and never `refused-not-configured` — the AI's absence must not touch the owner's ability to turn the switch off.
    - Assert in `refuses_on_when_unconfigured` that the manager's state is still `AutopilotOff` after the call, which is what "the switch stays off" means mechanically.
