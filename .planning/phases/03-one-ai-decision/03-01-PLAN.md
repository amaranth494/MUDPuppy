<objective>
Give the server a memory of what the game just said. A bounded, per-user ring of recent MUD output — telnet control bytes and ANSI colour codes stripped — is kept continuously from the moment a connection is live, so that when autopilot is switched on the driver can take one snapshot and have something to reason about immediately, including the text that was already on screen before the switch was flipped.

Purpose: D-01 says the decision fires immediately on `#AUTO ON` with no waiting for fresh output. That is only possible if the text is already being kept. D-04 fixes what "the current game text" means: a server-side rolling window, sized by a constant, ANSI-free, spanning the moment the switch was flipped. This plan is the read half of the phase's central slice and has no dependencies, so it is decided and proved by `go test` before anything calls it.
Output: `internal/session/window.go` with its tests, and a fifth user-keyed map on `Manager` with one accessor.
</objective>

    Declare `const RecentOutputWindowBytes = 8192` with a doc comment stating it is roughly two to four 80-column screens of plain text, that it is a server constant and deliberately not a profile setting (D-04), and that per-profile tuning is deferred to Phase 4.

    Declare `var ansiCSI = regexp.MustCompile("\\x1b\\[[0-9;]*[a-zA-Z]")` and `func stripANSI(b []byte) []byte` returning `ansiCSI.ReplaceAll(b, nil)`. Document that a CSI sequence split across two socket reads will not match and leaves a few stray bytes in the window — cosmetic noise for a language model to ignore, not a correctness bug, and explicitly not worth a terminal-emulation state machine here (RESEARCH Pattern 1). Document that this function is for the AI's snapshot only and is never applied to the browser-bound stream.

    Declare `type ringBuffer struct` holding a fixed `[]byte` of length `RecentOutputWindowBytes`, a write offset and a `filled bool` (or an equivalent byte-count field). Give it two methods:
    - `append(p []byte)` — copies `p` into the ring oldest-first-overwritten. When `len(p)` is larger than the ring, keep only the trailing `RecentOutputWindowBytes` bytes of `p`.
    - `snapshot() string` — returns the contents in chronological order (oldest first, newest last), and `""` when nothing has been written.
    Both are plain methods with no locking; the caller holds `m.mu`.

    Create `internal/session/window_test.go` in `package session` with `func TestWindowSnapshot(t *testing.T)` in the table-driven `t.Run` style of `internal/icm/icm_test.go`. Subtests, named so the `-v` PASS lines read as sentences:

    - `keeps_plain_text_untouched`: a plain line round-trips byte for byte.
    - `split_escape_sequence_is_tolerated`: append `\x1b[3` then `2mhello`; the call does not panic and the snapshot contains `hello` (the stray fragment is accepted, and the subtest's comment says so).
    - `empty_ring_snapshots_to_empty_string`.
    Add `func TestWindowRingBound(t *testing.T)`: append `RecentOutputWindowBytes + 500` distinguishable bytes across several calls; assert the snapshot length is exactly `RecentOutputWindowBytes`, that the last bytes written are present at the end, and that the first bytes written are absent.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MUD socket → `Manager` memory | Untrusted remote text is copied into a server-side buffer that will later be put in front of a language model |
| Websocket/REST goroutines → `Manager` maps | The read loop writes the ring while other goroutines read it |
| Go process → server log | Anything logged from this path would be MUD content |

| Threat ID | Category | Severity | Component | Disposition | Mitigating Task |
