<objective>
Make the decision. With autopilot engaged on a connected, policy-accepted profile, the driver takes the rolling window of recent game text, asks the configured model once with the profile's conduct rules and approach guidance carried verbatim, validates that the answer is a single plain game command, puts it through the ICM dispatcher in the automation execution context, and — only then — sends it to the game. The decision, the reasoning and the outcome are stored. Any failure sends nothing, says why, and lands the switch on off.

Purpose: this is the phase. ROADMAP criteria 1 and 4 are both settled here, and RESEARCH's central finding decides how: `Engine.Process()` short-circuits a plain command before `Dispatch` is ever reached, so a driver written the obvious way would ship a working demo with a false criterion 4. Plan 03-03 already built the test that tells those two worlds apart; this plan writes the code that has to pass it.
Output: a new `internal/driver` package with its tests, a decision store, the two hook points that fire it exactly once per engagement, and the wiring in `cmd/server/main.go`.
</objective>
