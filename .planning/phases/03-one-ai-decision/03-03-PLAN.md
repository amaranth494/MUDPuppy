<objective>
Wake the dormant engine. `internal/icm` has existed with a dispatcher, a safety checker and an `automation` execution context since before this project started, and nothing has ever imported it. This plan constructs exactly one engine in `cmd/server/main.go`, registers its four routes, proves by test that a plain game command in `ContextAutomation` really does pass `Dispatcher.Dispatch` and its `SafetyChecker`, and stops the browser adapter from quietly answering ICM questions by itself when the server call fails.

Purpose: ROADMAP criterion 4 is a claim about a code path, and RESEARCH's central finding is that the obvious code path does not satisfy it — `Engine.Process()` classifies `"north"` as pass-through and returns before `Dispatch` is ever reached, so a driver built on `Process()` would ship a green demo and a false criterion. The test written here is the one that can tell those two worlds apart, and it exists before the driver that depends on it.
Output: one engine instance and four live routes in the server, one diagnostic test in `internal/icm`, and an adapter that reports failures instead of hiding them.
</objective>

Go contract produced by this plan and consumed by plan 03-08:

- `func NewHandlerWithEngine(engine *Engine) *Handler` in `internal/icm` — the existing `NewHandler()` builds its own private engine, which would give the server two engines with two independent safety-checker states. The driver and the HTTP routes must share one.
- `cmd/server/main.go` holds `icmEngine := icm.NewEngine()` and passes `icmEngine.GetDispatcher()` to plan 03-08's driver constructor.

The mechanism this plan proves, verified in `internal/icm/dispatcher.go:187-224` and quoted verbatim in 03-PATTERNS.md: `Dispatch` runs `checkSafety` (circuit breaker, then rate limit, then queue depth) unconditionally before it consults `getHandler`. For a plain command with an empty operator family no handler exists, so `Dispatch` returns `(nil, nil)` — which means "safety approved, nothing further for ICM to do", and is the signal the driver waits for before calling `manager.SendCommand` itself. `Dispatch` never sends anything to any connection.
