# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope actually covered here** (per owner instruction — nothing else is in Phase 1 UI):
(a) the policy acceptance presentation shown the first time the AI Player section is opened for a profile, blocking settings until accepted;
(b) the AI settings editor: conduct rules, approach guidance, AI settings (model name, call cap per session, disengage threshold), blank meaning server default;
(c) the refusal message surface for the engage gate (text contract only — Phase 2 wires `#AUTO ON` to it).
No reconnect field anywhere in this contract.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-built React components, no Radix/base-ui/shadcn |
| Icon library | none — single-glyph Unicode/emoji characters used inline, matching `SECTIONS` icons in `SettingsPage.tsx` (⚙ ⌨ ⚡ ⚓ ⏱ 📦) |
| Font | `var(--font-mono)` = `'Courier New', Courier, monospace` (whole app is monospace; no separate UI font) |

**Why no shadcn:** The frontend (`frontend/package.json`) has no Tailwind, no `components.json`, no Radix. The existing UI is a fully hand-rolled retro-terminal design system (`frontend/src/index.css`): near-black background, neon-green accent, plain CSS classes (`.form-input`, `.btn`, `.settings-section`, etc.), custom properties for every token. The owner's explicit instruction for this phase is to match this existing look exactly and not invent a new design system, so shadcn is out of scope here. This is a project-level override of the standard shadcn gate, not an oversight.

**Known inconsistency, do not copy:** `frontend/src/pages/HelpPage.tsx` uses ad-hoc inline styles with a different blue/white palette (`#3b82f6`, `rgba(255,255,255,...)`). This is a legacy outlier, not the canonical system. The AI Player section lives inside `SettingsPage.tsx` beside Aliases/Triggers/Timers/Environment (CONTEXT D-01) and must follow those sections' CSS-class-based terminal-green pattern, not HelpPage's inline styles.

## Spacing Scale

Declared values (must be multiples of 4) — these are the project's existing tokens in `index.css`, reused as-is:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`--spacing-xs`, 0.25rem) | Icon gaps, inline padding |
| sm | 8px (`--spacing-sm`, 0.5rem) | Compact element spacing, form input padding |
| md | 16px (`--spacing-md`, 1rem) | Default element spacing, form-group gaps |
| lg | 24px (`--spacing-lg`, 1.5rem) | Section padding, `.settings-actions` top border spacing |
| xl | 32px (`--spacing-xl`, 2rem) | Layout gaps (not needed inside this section; used by parent overlay) |

2xl (48px) and 3xl (64px) are not defined in the codebase and are not needed for this phase — the AI Player section is a single column of form controls inside the existing `.settings-content` panel, not a new page layout.

Exceptions: none. Every spacing value in the new AI Player section must come from the tokens above (via the existing CSS classes below), no ad-hoc pixel values.

## Typography

Existing tokens in `index.css`, reused as-is:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px (`--font-size-sm`) | 400 (regular) | 1.5 |
| Body | 16px (`--font-size-base`) | 400 (regular) | 1.5 |
| Display | 20px (`--font-size-lg`) | 700 (bold) | 1.2 |
| Heading | 24px (`--font-size-xl`) | 700 (bold) | 1.2 |

Usage in this phase:
- **Heading (24/700)** — the section title `<h3>AI Player</h3>`, matching every other `.settings-section h3` (Environment, Timers, etc. all use `--font-size-xl`).
- **Display (20/700)** — the policy panel's own heading ("Safety and Abuse Policy") and the "Accepted" status line, when it needs to stand out from body text without competing with the section `<h3>`.
- **Body (16/400)** — policy text paragraphs, textarea content (conduct rules, approach guidance).
- **Label (14/400)** — `.form-label`, `.form-hint`, `.section-description`, the policy version line, dates.

Only two weights exist anywhere in this contract: 400 regular (body copy, labels, hints, input text) and 700 bold (headings, `.btn` text, emphasis). Never introduce 500/600.

## Color

Existing tokens in `index.css`, reused as-is — this is already a compliant 60/30/10 system:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a0a` (`--color-bg`) | Page background, `.settings-content` background, textarea/input background |
| Secondary (30%) | `#111111` (`--color-bg-secondary`) | Panel/card backgrounds: the policy text panel, `.automation-row`-style field groups if used |
| Accent (10%) | `#00ff00` (`--color-text`) | Reserved for: the "Accept Policy" button (`.btn-primary`), the "Save AI Settings" button (`.btn-primary`), focus border on inputs/textareas (`.form-input:focus`), the "✓ Accepted v…" status line, success messages (`.message-success`) |
| Destructive | `#ff4444` (`--color-error`) | Reserved for: error messages (`.message-error`), the engage-gate refusal banner text/border |

Accent reserved for: the two primary CTA buttons in this phase (Accept Policy, Save AI Settings), input focus rings, and positive/success confirmation text. Never used for body text, labels, or decorative elements.

No new hex values are introduced by this phase.

## Copywriting Contract

Plain, non-marketing, terminal-friendly — this is a single-owner MUD client, matching the existing copy voice ("Environment variables store reusable values used by automation rules.", "Number of lines to keep in terminal history (100-10000)").

| Element | Copy |
|---------|------|
| Primary CTA — policy gate | **Accept Policy** (single button, `.btn.btn-primary`; accepting the text is the confirmation per D-04 — no checkbox, no scroll gate) |
| Primary CTA — settings editor | **Save AI Settings** (`.btn.btn-primary`, matches "Save Variables" / "Save Timers" naming pattern already in the app) |
| Pre-acceptance state (this phase's "empty state" — nothing is configurable yet) heading | Safety and Abuse Policy |
| Pre-acceptance state body | Full served policy text, rendered as plain paragraphs (see Layout section). Below it: `Version {version}` on its own line, then the Accept Policy button. No other copy — no marketing framing, no "welcome" text. |
| Post-acceptance status line | `✓ Accepted v{version} on {YYYY-MM-DD}` — e.g. `✓ Accepted v1.0 on 2026-09-15`. Plain ISO date, not locale-formatted, to stay terminal-consistent. |
| Error state — load failure | `Failed to load AI settings` (matches existing `Failed to load variables` pattern; shown in `.message.message-error` with a Dismiss button) |
| Error state — save failure | `Failed to save AI settings` (same pattern as `Failed to save variables`) |
| Error state — policy load failure | `Failed to load policy` |
| Error state — accept failure | `Failed to record acceptance` |
| Engage-gate refusal (text contract for Phase 2) | `AI Player has not been configured for this connection. Accept the Safety and Abuse policy in AI Player settings before engaging autopilot.` with a link/button labeled `Open AI Player Settings` that navigates to that profile's AI Player section. This is the exact string Phase 2 should surface verbatim when `#AUTO ON` is refused by the gate (D-05). |
| Destructive confirmation | None in this phase. There are no delete actions in the AI Player scope (no reconnect field, no per-item lists to remove — conduct rules and approach guidance are single free-text fields, not repeating rows). |

Field-level copy (labels and hints, following the existing `.form-label` / `.form-hint` pattern seen in `EnvironmentPanel.tsx` and the General/Environment sections):

| Field | Label | Placeholder | Hint |
|-------|-------|-------------|------|
| Conduct rules | Conduct Rules | (none — textarea) | Plain-text rules handed to the model as-is. Blank means none. |
| Approach guidance | Approach Guidance | (none — textarea) | Free-text guidance on how the AI should play. Blank means none. |
| Model name | Model Name | Server default | Blank uses the server's configured default model. |
| Call cap | Call Cap (per session) | No cap | Blank means no cap on calls per session. |
| Disengage threshold | Disengage Threshold | Default | Blank uses the engine's built-in error handling: any AI failure shows an informative error, disengages, and regular play continues. It never crashes. |

## Layout & Component Reuse (phase-specific — extends the template because this phase introduces new screen content)

All markup reuses existing CSS classes from `frontend/src/index.css`; no new classes are required beyond the two noted below.

**Nav entry** (`SettingsPage.tsx` `SECTIONS` array): add `{ id: 'ai-player', label: 'AI Player', icon: '🤖' }`, positioned after `timers`/`environment` per D-01 ("beside Key Bindings, Aliases, Triggers, and Timers").

**Section wrapper:** `<div className="settings-section"><h3>AI Player</h3>...</div>` — identical wrapper to every other section.

**State 1 — not yet accepted** (the section's entire content is just this; nothing else renders):
- A panel using `.contextual-help`-style bordered box (or a new `.policy-panel` class with identical properties: `background: var(--color-bg-secondary); border: 1px solid var(--color-border); border-radius: var(--radius-md); padding: var(--spacing-md);`), scrollable (`max-height: calc(100vh - 380px); overflow-y: auto;` — same pattern as `.keybindings-list`).
- Inside: Display-size heading "Safety and Abuse Policy", Label-size "Version {version}" line, then the full policy text as Body-size paragraphs (reuse the paragraph/bold/list parsing approach from `HelpPage.tsx`'s `renderContent`/`renderInline`, but re-themed to `var(--color-text)`/`var(--color-text-dim)` instead of hardcoded blue/white — do not copy HelpPage's inline hex colors).
- `.settings-actions` row at the bottom with a single `.btn.btn-primary` "Accept Policy" button. No checkbox, no other control.

**State 2 — accepted:**
- A single Label-size line: `✓ Accepted v{version} on {date}`, styled like `.profile-hint` (dim, `var(--color-text-dim)`), colored with the accent green checkmark (`var(--color-text)`) for the ✓ only.
- Below it, the AI settings editor form:
  - `.form-group` + `.form-textarea` for Conduct Rules (min-height 120px, following `.form-textarea` pattern already defined for automation scripts).
  - `.form-group` + `.form-textarea` for Approach Guidance (min-height 120px).
  - `.form-group` + `.form-input` (text) for Model Name.
  - `.form-group` + `.form-input` (number) for Call Cap.
  - `.form-group` + `.form-input` (number) for Disengage Threshold.
  - `.settings-actions` row with `.btn.btn-primary` "Save AI Settings", disabled while saving (`Saving...` label, matching `EnvironmentPanel.tsx`'s `isSaving` pattern).
  - `.message.message-error` / `.message.message-success` above the form for load/save feedback, with a Dismiss button on errors — identical to `EnvironmentPanel.tsx`.

**Engage-gate refusal banner (Phase 2 surface, text contract only):** reuse the existing `.automation-error-banner` pattern (already used for the automation circuit breaker in `PlayScreen.tsx`) — a red-bordered inline banner containing the refusal copy above and a button/link to the AI Player section. Phase 1 only needs to guarantee the server returns this exact string; Phase 2 renders it.

## Claude's Discretion (visual contract only — does not change owner-visible behavior)

- Icon glyph for the AI Player nav entry: 🤖, chosen for consistency with the existing pictographic glyphs (⏱ 📦 ⚡ ⚓).
- Exact class name for the policy text panel (`.policy-panel` vs. reusing `.contextual-help`) — either satisfies the same visual properties; executor may pick whichever is less invasive to the existing stylesheet.
- Textarea min-height (120px) for Conduct Rules and Approach Guidance — larger than the existing 60px automation-script textarea because these fields hold longer free text, still a multiple of 4.
- Date display format for the acceptance stamp (`YYYY-MM-DD`) — no existing full-date pattern in the codebase to match; ISO format chosen to stay terminal-consistent rather than locale-dependent.
- Markdown rendering approach for the policy text (paragraph/bold/list splitting) may reuse the logic shape from `HelpPage.tsx`'s `renderContent`/`renderInline`, restyled with CSS custom properties instead of that file's hardcoded inline colors.

None of these affect what the owner sees in terms of information, wording, or interaction — only implementation-level styling choices, consistent with "no speed bumps" guidance.
