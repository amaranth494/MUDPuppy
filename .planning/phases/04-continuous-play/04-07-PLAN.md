<objective>
Put what the AI is trying to do, and what it has learned, in front of it — and frame every word of it as untrusted.

Two things happen here. First, D-13's prompt order: the profile's standing text verbatim, then the session goal, then the active Quest's bullets, then Session Memory, then the game-text window. That shape is what Phase 5's coaching and Phase 6's Historical Memory will add to, so it is worth getting right once. Second, the security consequence the memory model creates: Session Memory and Quest Memory are written **by the model, from game text**. A hostile room that cannot make the AI issue a command today can instead try to make it write a sentence into its own memory, where that sentence would come back as apparently-trusted standing context on every future decision. D-13's answer is that memory is delimited as untrusted data in both prompts, exactly as the window is, and that instructions found inside it are never followed.

The same plan closes D-24 (DR-3.1-01): the reviewer currently reads the first model's stated reasoning as though the first model were a trustworthy narrator, when that reasoning is just more text written after reading the same hostile window. It gets its own untrusted markers, and a corpus item is added that attacks precisely through that channel.

Purpose: REQ-continuous-loop's "plays toward it", REQ-reengage-reassess's "against the goal", and the new injection surface this phase opens.
Output: a `promptContext` threaded through both builders, an extended untrusted-data paragraph, the reviewer's wrapped reasoning, and the reviewer-channel corpus item.

Nothing in this plan writes memory — the model cannot yet propose a memory update, and Session Memory reads back empty until plan 04-08. What this plan proves is that when memory exists, it arrives framed correctly.
</objective>
