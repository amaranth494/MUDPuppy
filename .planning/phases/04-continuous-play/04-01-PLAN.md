<objective>
Make a multi-decision stint observable before building one. Today's driver tests can only describe a single decision: `fakeModels` holds exactly one canned answer, and `fakeSessions.DisengageAutopilot` always answers `(Off, true)` no matter what the switch was. Neither can express "the third decision failed after two good ones" or "the loop stopped because the switch went off" — the two sentences every Phase 4 safety limit is written in.

Purpose: D-20 puts all four mechanical limits under automated test, and the ROADMAP's own implementation note says the test scaffolding is created in this phase because this repository has near-zero coverage. This plan creates that scaffolding and proves it works by driving a stint through the *unchanged* Phase 3 decision path — so every later plan's test failure means the code is wrong, not the harness.
Output: a scripted model queue, a session double that runs the server's real autopilot state machine, an output-arrived signal double, and `loop_test.go` holding the first two tests that use them.

No production behaviour changes in this plan. The only non-test edit is one method added to the `Sessions` interface, which the real `*session.Manager` already implements.
</objective>
