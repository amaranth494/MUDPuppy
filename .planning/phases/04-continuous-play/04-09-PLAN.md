<objective>
Stop keeping the game's text forever. Every decision the AI has ever made stores the window of game text it was reading, and every session stores its transcript — and nothing has ever deleted either. Phase 3.1 made it worse in one specific way: a blocked decision stores the attack text verbatim, so the store now also accumulates hostile content. The owner's instruction at both reviews was the same: make a retention standard, with a way to clean it out on demand.

D-21 sets the standard: the snapshot stored beside a decision goes after seven days, session transcripts go after thirty, and the decision record itself — when it happened, what the AI was thinking, what it tried, what happened, and why it was blocked — is kept indefinitely, because that is the audit trail the whole project depends on. The memory model draws the same line in the owner's own words: a snapshot captured so a decision can be reconstructed "should be treated as a separate, pruneable artifact rather than as part of the AI's persistent memory". Session Memory and Quest Memory are memory, not captured text, and neither path touches them.

Purpose: D-21, closing DR-3-01 and DR-3.1-03 together, and answering the open data-handling question the policy's sections 5 and 6 left standing since Phase 3.
Output: a retention job with its two windows, an in-process nightly ticker with one log line per run, a per-profile immediate delete behind a confirmation, and the tests and copy that pin all of it.

Per-profile retention settings are explicitly out of scope; a server default is enough (04-CONTEXT Deferred).
</objective>

Claude's Discretion recorded for this plan (settled by the planner):
- The snapshot is cleared in place — the decision row keeps every other column and the window text becomes empty — rather than the row being deleted, because D-21 keeps the decision record forever.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stored captured text → time | Text kept indefinitely is a growing disclosure surface, and since Phase 3.1 it includes attack text |
| The delete endpoint → other owners' data | A destructive action scoped wrongly destroys someone else's record |
| The retention job → the audit record and the AI's memory | A prune that reaches too far destroys the evidence trail the project depends on, or the AI's own memory |
| The danger-zone control → an ordinary click | A destructive control beside a save button is a misclick away from data loss |

## STRIDE Threat Register

| Threat ID | Category | Severity | Component | Disposition | Mitigation |
|-----------|----------|----------|-----------|-------------|------------|
| T-4-08 | Information Disclosure (data protection) | Medium | every session transcript and every decision window, including blocked decisions' attack text, kept forever with no way to clear it | mitigate | Seven-day snapshot and thirty-day transcript windows enforced by a daily in-process job, plus a per-profile immediate delete (D-21, closing DR-3-01 and DR-3.1-03) |
| T-4-15 | Denial of Service (destructive over-reach) | High | a prune or a delete removing decision rows, reasoning, outcomes, block reasons, Session Memory or Quest Memory | mitigate | The statements touch `window_text` and `game_session_lines` only, asserted mechanically by `TestRetention_TouchesOnlyCapturedText` and `TestRetention_LeavesMemoryAlone` |
| T-4-09 | Spoofing / broken access control (IDOR) | High | the delete endpoint aimed at a connection the caller does not own | mitigate | `getProfileByConnectionID` before any store call, re-proven by the harness's not-owned step (plan 04-10) |
| T-4-30 | Denial of Service (misclick) | Medium | a destructive control adjacent to an everyday save action | mitigate | Its own separated block with a top border, an unconditional scope-stating hint, and a two-step inline confirmation (04-UI-SPEC §6) |
| T-4-31 | Denial of Service (self-inflicted outage) | Low | a retention run erroring and taking the server or play down with it | mitigate | The job runs in its own goroutine, logs its error and continues; nothing in the play path depends on it |
| T-4-05 | Information Disclosure | Low | the retention log line carrying row text | mitigate | Counts, day numbers, a duration and ids only |
| T-4-SC | Tampering (supply chain) | Low | `go.mod`, `frontend/package.json` | accept | No package is added |
</threat_model>
