# Phase 3.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Derived from `03.1-RESEARCH.md` §Validation Architecture. The planner fills the Per-Task map with real task IDs; the executor flips statuses.
>
> **Evidence rule (owner-directed, binding).** Every success criterion and acceptance criterion is proven by one of exactly two artifact types: a **canned report** (a repeatable script or test run whose output is captured verbatim into a file) or a **screenshot** (an image of the browser as the owner sees it, no devtools, terminal, or raw JSON in frame). A server log excerpt captured to a file counts as a canned report. **Running a database query is not evidence** and no row in this document may cite one. Every row's Evidence column names a file under `.planning/phases/03.1-prompt-injection-review/evidence/`.
>
> **Corpus rule (D-11, D-14).** The live corpus test runs only from the dev machine, only when `MUDPUPPY_LIVE_CORPUS=1` and the Gemini environment variables are set, never on staging. The red-team report and every `[AI-PLAYER]` log line carry ids, stage names, verdicts and lengths only, never the window text or the command.

| **Estimated runtime** | ~15 seconds for `go test` on the touched packages (no `-race`: cgo is unavailable on the dev machine, and the test report must say so); ~40 seconds for `npm run build`; ~2 to 5 minutes for the live corpus run (two real Gemini calls per corpus item after the build); ~20 seconds for the harness against staging |

## Sampling Rate

- **After every task commit:** Run `go test ./internal/driver/... ./internal/gemini/... ./internal/store/... -v`
- **After every plan wave:** Run `go test ./...` and `cd frontend && npm run build`
- **Before the build waves start:** the live corpus test has been run once against the pre-build code and the BEFORE report is filed (plan 03.1-01, wave 1)
- **Before `/gsd:verify-work`:** Full suite green; the live corpus test run again, unmodified, in strict mode against the finished build with the AFTER report filed; harness self-test and staging report captured; staging screenshots and `[AI-PLAYER]` log excerpt filed (plan 03.1-07)
- **Max feedback latency:** 60 seconds (excluding the live corpus run, which is a phase gate, not a per-task check)
