<objective>
Make the HTTP-reachable half of this phase provable by one command. `scripts/verify-phase3-1.sh` drives the AI settings sub-resource and the decisions endpoint against a running MUDPuppy server and writes a report that says, criterion by criterion, whether Phase 3.1's reachable half holds: the Never-issue list round-trips and is capped, and a blocked decision reads back with its outcome and reason. What the script cannot reach it prints as SKIP naming the test or screenshot that proves it instead.

Purpose: the owner's evidence rule needs a repeatable script whose output is captured verbatim, and D-14 forbids proving "a blocked row exists" with a query. This is the only route from the blocked decision to a canned report. The harness also has to be able to fail before anyone believes it, which is what the negative self-test is for.
Output: the script, a correct-server fixture set and a deliberately wrong one.

This is Phase 3's `scripts/verify-phase3.sh` again, pointed at this phase's two endpoints. Follow its shape exactly rather than inventing a second harness style.
