<objective>
Show the owner what the AI tried to do and why it was stopped. A blocked decision arrives on the same `ai` event and the same decisions endpoint a sent decision does, and it renders as a decision card — the reasoning, then `Blocked → the command`, then the reason underneath — with a warning-coloured left border, plus one bracketed line in the terminal naming the blocked command. The autopilot badge does not move and no disengage notice appears, because nothing failed.

Purpose: D-07 and the owner-visible half of D-08. The core value of this project is that the owner always sees what the AI is doing and why; a defence that silently swallowed a steered command would break that promise more quietly than the attack would. This plan also closes RESEARCH Pitfall 5: the panel's existing reload mapping puts the notice in the command slot for every non-sent outcome, which would drop the very command the phase exists to show, and only after a refresh.
Output: a fourth outcome in the payload union, a blocked decision card with its reason line, a terminal line, and three CSS rules built from existing custom properties.

Every string, colour and layout choice here is locked in `03.1-UI-SPEC.md`. Nothing in this plan is open to interpretation.
</objective>

The server composes the whole reason string and the panel renders it verbatim — the frontend adds no prefix, no label and no paraphrase. What arrives is either `Matched Never-issue entry: "give"` or `Reviewer blocked: ` plus the reviewer's sentence (plans 03.1-03 and 03.1-04), which is why 03.1-UI-SPEC.md needs no separate layer badge: the reason names its own layer.

Locked copy and colour, from `03.1-UI-SPEC.md`'s Copywriting Contract and Color section:

| Surface | Exact form | Colour |
|---------|-----------|--------|
| Panel command line, blocked | `Blocked → {command}` | `--color-warning` |
| Panel reason line | the server's reason string, verbatim | `--color-text-dim` |
| Terminal line | `[AI-ASSIST blocked > {command}]` | ANSI `brightyellow` |
| Panel command line, sent (unchanged) | `→ {command}` | `--color-ai-accent` |
| Failure and refusal notices (unchanged) | unchanged | `--color-error` |

`--color-ai-accent` stays reserved for a command that was actually sent and `--color-error` for a disengage; a block is neither, and `--color-warning` already means "autopilot is still ON but not acting". No new custom property, no new font size, no new weight, no icon and no emoji.
