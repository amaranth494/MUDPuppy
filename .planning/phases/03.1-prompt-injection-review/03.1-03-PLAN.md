<objective>
Put two things between the model's answer and the game that were not there before: a prompt that says the game text is untrusted data rather than instructions, and a mechanical list of commands the owner has forbidden that is checked in Go before anything else looks at the command. A command caught by that list is not a failure — nothing is sent, the switch stays ON and idle, and the owner gets a decision row saying what the AI wanted to type and why it was stopped.

Purpose: D-01, D-02 and the first half of D-04's order (shape validation → Never-issue → reviewer → ICM dispatch → send). This plan also introduces the `blocked` outcome itself — `recordBlocked`, the fourth accepted outcome value, and the log line — because both blocking layers need it and the reviewer (plan 03.1-04) reuses it unchanged.
Output: a hardened system instruction, a wrapped window, `matchNeverIssue`, `recordBlocked`, and the tests that prove a block does not knock the switch off.

The single highest-risk line in this phase is the one that must **not** be copied: `recordFailure` calls `DisengageAutopilot` and `recordBlocked` must not (RESEARCH Pitfall 1). Every blocked test case asserts zero disengages positively, not merely the absence of a failure.
</objective>

Every one of these checks lives in `internal/driver` in front of the dispatcher; none of them may move into `internal/gemini`, which stays ignorant of prompt and command content (the doc-comment discipline plan 03-02 set).

The delimiter this phase adopts is the literal pair `<GAME_TEXT>` and `</GAME_TEXT>`, chosen here and used identically by the reviewer call in plan 03.1-04. The window is wrapped exactly once, and the wrapped string — never the raw one — is what both model calls receive (RESEARCH Pitfall 2).

| Layer | `FailureKind` | `Notice` |
|-------|---------------|----------|
| Never-issue list | `never-issue` | `Matched Never-issue entry: "{entry}"` with the entry exactly as the owner wrote it |
| Reviewer (plan 03.1-04) | `reviewer` | `Reviewer blocked: {the reviewer's one-sentence reason}` |

A block prints no notice of its own about autopilot state: the absence of a disengage notice is the signal that the switch stayed ON (03.1-UI-SPEC.md, D-06).

| Game text → the model's prompt | Untrusted remote text, including other players' speech, is put in front of a model asked to produce a command |

| Driver → the server log | A new stage and a new outcome mean new log lines |
