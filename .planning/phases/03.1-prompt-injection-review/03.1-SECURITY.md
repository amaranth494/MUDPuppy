## Trust Boundaries (consolidated across all seven plans)

| Boundary | Plans | Description |
|----------|-------|--------------|
| Corpus text → the model's prompt / the owner's Gemini quota | 03.1-01 | Deliberately hostile text is put in front of the real model on the owner's key; each item spends one or two real calls |
| Test process → the evidence file | 03.1-01, 03.1-06, 03.1-07 | Whatever a runner or harness prints is committed to the repository |
| Dev machine → staging | 03.1-01 | The live corpus test must never execute inside a Railway environment |
| Browser → `PUT /api/v1/profiles/{connection_id}/ai-settings` | 03.1-02 | Owner-supplied free text becomes a stored profile field fed to two models and a matcher |
| Profile row → the driver's decision path | 03.1-02 | The stored Never-issue list becomes a security control read on every decision |
| Migration → the live database | 03.1-02, 03.1-07 | A failed migration is a `log.Fatalf` at startup and takes staging down |
| Game text → the model's prompt | 03.1-03 | Untrusted remote text, including other players' speech, is put in front of a model asked to produce a command |
| Model answer → the Never-issue matcher | 03.1-03 | The chosen command is judged mechanically before anything else sees it |
| Driver → the ICM dispatcher | 03.1-03 | Nothing may reach the dispatcher until shape validation and the Never-issue list pass |
| Game text → the reviewer's prompt | 03.1-04 | The same untrusted text the player model saw is shown to the model judging it |
| Reviewer verdict / transport failure → the send decision | 03.1-04 | A boolean from a second model call now gates whether a command reaches the game; the absence of a verdict must block as hard as a negative one |
| Server `ai` event / decisions endpoint → browser panel and terminal | 03.1-05 | Model-derived and game-derived text is rendered to the owner, live and after reload |
| Harness → a running server with the owner's session cookie | 03.1-06 | The script authenticates as the owner and writes to a real profile |
| Repository → Railway staging; owner's browser session → the live MUD and model | 03.1-07 | The deployed binary may diverge from the repo; the walkthrough drives the real session, socket, driver and vendor call with hostile text typed by the owner |
