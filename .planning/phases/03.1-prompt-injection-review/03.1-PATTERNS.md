**`recordFailure` — the sibling `recordBlocked` must copy this shape minus one line (verified verbatim, lines 288-330):**
```go
func (d *Driver) recordFailure(userID, connectionID string, userUUID, connUUID uuid.UUID, gameSessionID *uuid.UUID, modelName, window, reasoning, command, failureKind string) {
    notice := failureNotices[failureKind]
    outcome := "failed"
    if failureKind == failureICMRefused {
        outcome = "refused"
    }

    decisionID := ""
    if d.decisions != nil {
        id, _, err := d.decisions.InsertDecision(store.DecisionRecord{
            UserID: userUUID, ConnectionID: connUUID, GameSessionID: gameSessionID,
            ModelName: modelName, WindowText: window, Reasoning: reasoning, Command: command,
            Outcome: outcome, FailureKind: failureKind, Notice: notice,
        })
        if err == nil {
            decisionID = id.String()
        }
    }

    d.notify(userID, Event{
        ID: decisionID, Kind: "system", Reasoning: reasoning,
        Outcome: outcome, Message: notice, Timestamp: time.Now().UTC().Format(time.RFC3339),
    })

    d.sessions.DisengageAutopilot(userID, "ai-failure")   // <-- the ONE line recordBlocked must NOT copy (D-06)

    d.logDecision(userID, connectionID, decisionID, "failed", modelName, outcome, failureKind, len(window), len(command))
}
```
`recordBlocked` differs in exactly three ways from this: `Outcome: "blocked"` (fixed, not derived from `failureKind`), `Kind: "decision"` (not `"system"`, so the command shows — D-07), and **no** `DisengageAutopilot` call (D-06, Pitfall 1 in RESEARCH.md). `Command: cmd` must also be set on both the `DecisionRecord` and the `Event` (unlike `recordFailure`, which only sets `Command` because it is passed one, but a `recordBlocked` call always has a real chosen command by construction — the block happens strictly after `validateCommand` succeeds).

**`buildSystemInstruction` — the exact function the delimiter/untrusted-data sentence and the Never-issue block join (verified verbatim, lines 388-400):**
```go
func buildSystemInstruction(profile *store.Profile) string {
    var b strings.Builder
    b.WriteString("You are playing a text-based multiplayer game on behalf of its owner. ")
    b.WriteString("You are shown the game's most recent output and must decide the single next command to send.\n\n")
    b.WriteString("Conduct rules:\n")
    b.WriteString(profile.ConductRules)
    b.WriteString("\n\nApproach guidance:\n")
    b.WriteString(profile.ApproachGuidance)
    b.WriteString("\n\nRespond with a short plain-language reasoning of one to three sentences written for the owner, ")
    b.WriteString("and exactly one command, written exactly as it would be typed at the game's prompt, ")
    b.WriteString("with no leading '#', '@', '$' or '%' character.")
    return b.String()
}
```
The call site to change is line 238: `d.models.GenerateContent(context.Background(), entry.Endpoint, entry.ModelName, entry.APIKey, systemInstruction, window)` — the fifth argument (`window`) must become the `<GAME_TEXT>`-wrapped string (D-01), and this same wrapped string is reused for the reviewer call (Pitfall 2 — do not let the reviewer see the raw `window`).

**`validateCommand` — unchanged, the existing security-boundary precedent every new gate follows (verified verbatim, lines 409-432):** trims, rejects empty/multi-line/`#@$%`-prefixed/oversize/control-character input, returns `(trimmed, "")` on success or `("", failureKind)` on failure. `matchNeverIssue` (new) and the reviewer's interpretation (new) are the same "mechanical backstop that does not care whether the model behaved" philosophy, applied to content rather than shape.

**Failure-kind constants and notices to extend (verified verbatim, lines 32-55):** `failureAPIError`/`failureRateLimited`/`failureMalformed` already exist and are exactly the three kinds D-09's reviewer-failure mapping reuses — no new failure kind or notice string is needed for the reviewer's own transport/rate-limit/malformed errors, only a new code path that maps a `ReviewCommand` error the same way the existing `GenerateContent` error mapping does at lines 248-254.
