<objective>
Add the judgment layer. After the model has chosen a command and after the mechanical list has let it through, a second call to the same model is shown the conduct rules, the Never-issue list, the delimited game-text window and the command with its stated reasoning, and asked two questions: does this command break a conduct rule, and does it follow an instruction embedded in the game text rather than respond to the game situation. A yes to either stops the command with the reviewer's own sentence as the reason. A reviewer that cannot answer at all stops the command too — and disengages, because an unreviewed command must never reach the game.

Purpose: D-03, D-04's third checkpoint, and D-09. This is the layer that catches what a prefix list cannot: a rephrasing, a synonym, a plausible-looking command that only makes sense if you believed the room's instructions. It is also the layer most exposed to the attack it defends against, which is why the reviewer receives the same delimited, untrusted-framed window as the player call and why the residual — a reviewer that is itself talked round — goes on this phase's security agenda rather than being claimed as closed.
Output: `ReviewCommand` on the Gemini client with its own constrained schema, the reviewer stage wired into `HandleEngage` in D-04's position, and a table test separating a block from a failure.

D-05 is accepted and recorded: this doubles the Gemini calls per decision on a free-tier key. The per-session call cap remains the cost protection and Phase 4 counts both calls against it.
</objective>
