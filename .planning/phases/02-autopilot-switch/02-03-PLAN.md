<objective>
Make taking the wheel instant and lossless. Every command the browser sends now carries a flag saying whether a person typed it or the browser's own automation fired it, and the one place server-side where a command crosses into the game reads that flag: a human-sourced command disengages autopilot first and is then sent exactly as it always was, while a trigger- or timer-fired command passes through with autopilot untouched.

Purpose: ROADMAP criterion 2 in full. The decision is enforced on the server, not in the browser, and it fails in the safe direction — an absent, empty or unrecognised flag counts as human, so a stale bundle or a forged value can only cause an unwanted disengage, never a silent bypass (RESEARCH Pitfall 3).
Output: an extended `internal/session/websocket.go` and a new `internal/session/websocket_test.go` proving the rule without opening a websocket.
</objective>

Wire contract produced by this plan and consumed by plan 02-04 (fixed here):

- Inbound: `WSMessage` gains `Source string` with json tag `source,omitempty`, meaningful only on `data` messages. The browser sends its existing `CommandSource` values: `user`, `alias`, `trigger`. The server's rule is an allowlist of automation labels — only `trigger` and `timer` are automation; everything else, including absent, empty and unknown, is human.
- Outbound: new message type constant `MsgTypeAutopilot = "autopilot"`, carried as `WSMessage{Type: MsgTypeAutopilot, Status: <state>, Data: <cause>}` where state is `on`, `waiting` or `off` and cause is one of plan 02-01's cause values. Phase 2 pushes exactly one cause over this channel: `wheel-grab`. Reusing the existing `Status` and `Data` string fields is deliberate — no new struct field, no new registry of connections.

Why there is no broadcast registry: no per-user websocket connection map exists in this codebase, and building one is out of scope for this phase (RESEARCH Anti-Patterns). The push here is best effort on the connection already in scope; correctness after a refresh or in a second tab comes from the 15-second `GET /api/v1/session/status` poll that plan 02-02 extended, not from this push. A failed push must never block or fail the command.
</context>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser websocket → session websocket handler | Every field on an inbound `data` message, including the new `source`, is client-controlled and untrusted |
| Websocket goroutine → `Manager` autopilot map | The grab mutates shared state that the REST handler also writes |
| Websocket handler → browser | The outbound autopilot push reaches whoever holds that connection |
