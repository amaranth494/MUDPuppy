<objective>
Make `#AUTO` a directive the owner can type, and make every outbound command say who sent it. `#AUTO ON`, `#AUTO OFF`, `#AUTO STATUS` and a bare `#AUTO` join the same `#` grammar that already carries `#ECHO`, `#LOG`, `#HELP` and `#TIMER`; each one calls the server and prints exactly the line the approved UI contract specifies. In the same pass, the `CommandSource` the engine already assigns at every origination point stops being dropped on the way to the websocket, so the server's wheel-grab has something truthful to read.

Purpose: this is the browser half of ROADMAP criteria 1 and 2. Two known traps are closed here on purpose: a blank Enter bypasses the automation engine entirely and must still be labelled human (RESEARCH Pitfall 2, D-07), and a typed `#` directive that emits game commands must label those commands automation so a directive can never take the wheel from itself (D-08).
Output: five extended frontend files, no new dependency, and a green `npm run build` which runs `tsc` first.
</objective>

Server contract this plan consumes (fixed by plans 02-02 and 02-03, do not renegotiate):

- `POST /api/v1/session/autopilot` with `{ "action": "on" | "off" | "status", "connection_id": "<uuid>" }`.
- Response `{ state, outcome, gate_allowed, gate_message?, policy_version? }` where `state` is `on`, `waiting` or `off` and `outcome` is one of `engaged`, `disengaged`, `already-on`, `already-off`, `refused-gate`, `refused-no-session`, `status`.
- `GET /api/v1/session/status` carries `autopilot_state` on every response.
- The outbound websocket message `{ type: "autopilot", status: <state>, data: <cause> }`; Phase 2 sends one cause, `wheel-grab`.
- Outbound `data` messages gain `source`; the server treats only `trigger` and `timer` as automation, everything else as human.

Owner-visible copy, from 02-UI-SPEC.md's Copywriting Contract — reproduce character for character, including the brackets:

| Outcome | Line | Colour name |
|---------|------|-------------|
| `engaged` | `[Autopilot engaged]` | brightgreen |
| `disengaged` | `[Autopilot disengaged]` | white |
| `already-on` | `[Autopilot is already on]` | white |
| `already-off` | `[Autopilot is already off]` | white |
| `refused-gate` | `[` + the response's `gate_message` + `]` | red |
| `refused-no-session` | `[Autopilot needs a connected game; connect first]` | red |
| `status` | `Autopilot: {STATE}. Engage gate: {gate result}.` — no brackets | brightyellow |

`{STATE}` is the response's `state` uppercased. `{gate result}` is `passed (policy v{policy_version} accepted)` when `gate_allowed` is true, and the response's `gate_message` verbatim when it is false. Worked example from the UI contract: `Autopilot: OFF. Engage gate: passed (policy v1.0 accepted).`
